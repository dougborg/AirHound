# AirHound Flipper bridge v1 (proposed frozen codec contract)

Transport: official RPC AppDataExchange bytes, one complete AHFB message per protobuf event. Max payload256, message300 bytes. No arbitrary UART commands. All multibyte integers little-endian, reject any wrong length/reserved bits/type/version. No raw JSON or string commands.

Header44: magic[0..4] AHFB; version[4]=1; type[5]; flagsu16[6]=0; request_idu32[8]; host_nonce[12..28]; app_instanceu64[28]; message_sequenceu32[36]; payload_lengthu16[40]; reservedu16[42]=0.

Host nonce16 cryptographically random nonzero; app instance nonzero random64 generated at app launch, not a firmware boot ID. Initial Hello uses instance0, seq0. FAP binds once to nonce, returns instance; every subsequent message must match both. The first AHFB response is Hello with sequence1 and the original Hello requestID. Do not send a separate AHFB Ack or unsolicited Status before it; the outer RPC transport acknowledgment remains separate. Host messages sequence0 (requests use request IDs), device messages strictly increase from1 across all kinds, no wrap; exhaustion terminates session. Device gaps mean delivery loss; fail current capture and require explicit new run, never silently continue binary framing. Unexpected nonce/instance rejected, not reset.

Host types: 1 Hello(empty); 2 StartBeacon(empty); 3 Pause(empty); 4 Stop(empty); 5 Heartbeat(empty). Nonzero strictly increasing requestID including heartbeats; no automatic retry of mutating requests, duplicate request ID is rejected without UART side effects. Ready means command-ready, not radio-stopped. Launch and Hello open no UART. Start is accepted from Ready/Paused and performs an explicit Stop preflight with observed stop text and clean quiet framing before sending the passive beacon command; no Start before Hello. Start again while capturing is rejected. No separate Resume: explicit StartBeacon from Paused starts a new stream generation/header. Stop is terminal for this app session; no automatic RF restart after transport loss/watchdog/error.

Device types:
0x81 Hello: capabilitiesu32 (bit0 passive_beacon; bit1 pause; bit2 watchdog; bit3 explicit_stop_completion; no unknown bits), compiled Flipper C ABI APImajoru16, APIminoru16 (not firmware or RPC version), UARTbaudu32, watchdog_msu32=3000, app_version_len:u8 + ASCII package version (1..32), source_revision_len:u8 + ASCII git revision (0 unknown or40hex), source_modified:u8 (0 clean,1 modified,2 unknown). This is app self-report; backend obtains Flipper firmware/UID separately, AWOK firmware unknown unless separately verified.
0x82 Ack: request_type:u8, result:u8 (0 accepted,1 invalid_state,2 invalid_payload,3 stale_request,4 unavailable). HeaderrequestID echoes request. Accepted means queued/validated, NOT UART transmitted or RF stopped.
0x83 Status fixed48: state:u8 (0 Ready,1 Preflight,2 Capturing,3 Stopping,4 Paused,5 Stopped,6 Failed), cause:u8 (0 none,1 user_pause,2 user_stop,3 watchdog,4 transport_lost,5 uart_loss,6 framing,7 preflight_failed,8 queue_loss,9 cancelled,10 stop_ack_deadline,11 stop_frame_incomplete,12 stop_drain_deadline,13 late_paused_uart,14 stop_replies_incomplete), evidenceu16 (bit0 preflight_stop_text_seen,bit1 start_text_seen,bit2 stop_text_seen,bit3 bounded_stop_complete; text unauthenticated; bits0/1 cumulative within generation, bits2/3 belong to current stop request), generationu32, app_uptime_msu32, uart_rx_bytesu64, uart_dropped_bytesu64, uart_error_eventsu64, rpc_dropped_messagesu64, unread_ring_bytesu32. HeaderrequestID is the causing lifecycle request (Start for Preflight/Capturing, Pause for Stopping/Paused, Stop for Stopping/Stopped), unchanged by heartbeats; initial Ready and autonomous events use0. An accepted lifecycle Ack precedes its statuses. No boolean physical RF-stop certainty. Latest cumulative counters remain valid across generations and never decrease.
0x84 Raw: generationu32, app_uptime_msu32, rawUARTbytes1..248. Includes original Marauder serial frame markers/console. Device timestamp is app receive uptime, not RF capture timestamp. Preserve producer PCAP boot-relative timestamp; host receipt location explicitly association only. Generation increments before the first Preflight status for each explicit Start. Raw is permitted during Preflight/Capturing/Stopping, after that generation status. Preflight console is not capture input. After observing preflight stop text and quiet drain, send an updated Preflight status with evidence bit0 BEFORE issuing UART Start; the host resets its parser at that boundary and accepts a fresh global header even if it precedes the later Capturing/start-text status. Generation starts1 on explicit Start and increments without wrap. It identifies a capture generation within this FAP app instance, not an AWOK hardware boot. Raw messages have header requestID0. Reset incremental PCAP state on each generation; no gap repair.

Heartbeat every1s, device watchdog3000ms refreshed only by valid bound heartbeat/control, never by generic transport traffic. UART owner has independent nonblocking loop, local watchdog stop and bounded acknowledgment drain, no filesystem/UI/RPC wait. RPC sender uses bounded queue; enqueue failure increments loss and requests local stop; status may only be delivered later. Consumer must treat loss or missing final status as incomplete/stop unknown. Session close callback requests local stop; reset, hung HAL, power loss remain unknown. No claimed all-circumstances stop guarantee.

Stop from Ready before any UART generation is an explicit exception: accepted Ack then Stopped with generation0, cause2, evidence0 and all UART counters/unread bytes0. This closes the app session without opening UART; radio state remains unverified. After any Start/UART ownership, the normal stop evidence contract applies.

Pause/Stop: Ack accepted first if available. The first Stopping status for each new accepted stop request clears bits2/3 BEFORE sending UART Stop; only a new observed acknowledgment can set it. A prior Pause acknowledgment cannot satisfy a later Stop. Stop may escalate an in-progress Pause using a new request ID without extending the original stop deadline; repeated Stop while already stopping for Stop is rejected. Then Paused/Stopped only after exact firmware text replies account for every issued UART Stop (including retries and earlier outstanding commands during escalation), plus framing/quiet drain. The new request cannot credit replies already observed before it. Late input after completed Pause fails closed with cause13; it is not automatically called malformed framing. A fresh stop acknowledgment must be observed within1s of its command; the first acknowledgment starts a fixed2s drain allowance, capped at3s from the original stopping transition. Repeated text/heartbeats do not renew these clocks. Pause-to-Stop escalation resets its request-scoped acknowledgment clock/witness but retains the original3s ceiling. A failed user stop reports cause10 for missing/late acknowledgment, cause6 for malformed framing, cause11 for an incomplete frame at the drain deadline, cause14 when the first reply was seen but other issued Stop replies remain outstanding, or cause12 when quiet completion was not observed before the drain/absolute deadline. Existing watchdog/transport/loss causes remain preserved. These additive cause IDs keep the v1 wire layout; older codecs reject unknown causes and fail closed. On missing ack => Failed with stop evidence false/unknown, not clean stopped. Source release only after bounded teardown and process/app ownership guard. No unrelated app close or device reset. Launch is no-RF; no channel assignment in v1, fixed currently configured AWOK channel remains unknown unless raw frames independently report it.

Codec goldens: every header integer boundary, max payload300, truncated/excess bytes, reserved bits, wrong enum/state, unknown version, nonce/instance mismatch, sequence/request wrap, malformed length/version text. Stateful tests: Hello no RF, duplicateStart no second UART write, invalid heartbeat cannot extend watchdog, pause/stop evidence vs accepted ack, full queue still stops, gaps no decoder splice, disconnect no resume.

The shared allocation-free codec is `companions/flipper/src/bridge.rs`; host and FAP use the same implementation. Host source integration is under development and has not been accepted on physical hardware.

Completion capability (bit3) is required before Start by the matching host; older
hosts reject the new capability and the new host rejects an older producer that
lacks it. This deliberately prevents silently applying new completion semantics
to an old artifact. The 48-byte Status layout remains unchanged.

`bounded_stop_complete` is set only after every issued Stop has an observed reply,
framing is complete and not malformed, and the required quiet/minimum-stop interval
has elapsed within the existing first-reply, drain and absolute deadlines. A known
UART/RPC loss or unread ring counter revokes this bit at final publication, including
when the controller was already Failed. New Pause/Stop requests clear both
request-scoped bits before UART output. Normal completed capture lifecycle evidence
is therefore 15 → 3 → 15 for Pause → fresh Finish; generation0 no-UART Stop remains0.
Autonomous failures retain their original cause and failed health regardless of the
completion bit. Failed/cause3/evidence7 alone is not stop-completion evidence: it can
mean a first reply was observed but a retry reply or quiet/framing completion never
arrived. Failed/cause3/evidence15 reports the bounded observed completion separately
from the failed session. Neither value authenticates firmware text or proves
physical RF silence. Historical acceptance using capabilities7/evidence7 remains
scoped to its exact prior artifact and cannot establish the new watchdog outcome.
